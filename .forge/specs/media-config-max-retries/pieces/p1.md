# p1 — Configurable media generation max-retries

## Summary

Add an env-overridable `maxRetries` setting to `MediaNetworkConfig` and
wrap scene-image and background-music generation in the existing
`Retry.withRetry`, so transient (retryable) media failures are retried up
to the configured number of times.

## Changes

### Config
- Add field `maxRetries: Int = 2` to the `MediaNetworkConfig` case class
  (`src/main/scala/org/llm4s/szork/api/MediaNetworkConfig.scala`).
- In `MediaNetworkConfig.load`, read `SZORK_MEDIA_MAX_RETRIES` via the
  `ConfigReader`, parse it as an Int, and fall back to the default when the
  variable is absent, non-numeric, **or negative** — mirroring the existing
  timeout parsing.

### Image generation
- In `ImageGeneration.generateSceneWithCache`
  (`src/main/scala/org/llm4s/szork/media/ImageGeneration.scala`), wrap the
  provider `imageClient.generateImage(...)` call (and its result mapping to
  `SzorkResult[String]`) in `ErrorHandling.Retry.withRetry(maxAttempts =
  MediaNetworkConfig.instance.maxRetries + 1) { ... }`.
- The disabled-client path and the cache-hit fast path must remain
  **outside** the retry block — a cache hit or a disabled client must not
  be retried.

### Music generation
- In `MusicGeneration.generateMusicWithCache`
  (`src/main/scala/org/llm4s/szork/media/MusicGeneration.scala`), wrap the
  generation request that yields the `SzorkResult` in
  `ErrorHandling.Retry.withRetry(maxAttempts =
  MediaNetworkConfig.instance.maxRetries + 1) { ... }`.
- Keep the cache-hit / not-available fast paths outside the retry block.
- Do **not** alter the internal `pollPrediction` poll loop.

### Logging
- Include the effective `maxRetries` value where `MediaNetworkConfig`
  values are logged (or add a one-line log of the media network config on
  load if none exists), consistent with existing config logging style.

## Acceptance criteria

1. `MediaNetworkConfig` has a `maxRetries: Int` field with a default value
   of `2`.
2. With `SZORK_MEDIA_MAX_RETRIES` unset, `MediaNetworkConfig.load(reader)`
   returns `maxRetries == 2`.
3. With `SZORK_MEDIA_MAX_RETRIES=5`, `MediaNetworkConfig.load(reader)`
   returns `maxRetries == 5`.
4. With `SZORK_MEDIA_MAX_RETRIES` set to a non-numeric value (e.g. `"abc"`)
   or a negative value (e.g. `"-1"`), `load` returns the default `2`.
5. With `SZORK_MEDIA_MAX_RETRIES=0`, `load` returns `0`, and image/music
   generation performs exactly one attempt (no retry) — reproducing the
   pre-feature behaviour.
6. A retryable image-generation failure is retried until it succeeds or the
   configured attempt budget (`maxRetries + 1`) is exhausted; a
   non-retryable failure is **not** retried. (Demonstrated via a test using
   a fake/stub image client that fails N times then succeeds.)
7. The same retry behaviour holds for music generation.
8. A cache hit (image or music) returns immediately and triggers zero
   generation attempts and zero retries.
9. New/changed unit tests live alongside the existing media config tests
   (e.g. extend `MediaNetworkConfigSpec`), and `sbt compile` and
   `sbt test` pass.

## Out of scope

- TTS/STT retries, LLM/narrative retries.
- Changes to `withRetry`, backoff timing, or any `retryable` flag.
- Per-provider retry configuration.
